Window motion: implementation and source references
2026-10-28

Scope and implementation

Dock minimization and restoration use a deformable, full-resolution window
surface. A first launch can use a short expansion at its final window position.
These are separate from the icon animation. Both durations support 120-600 ms;
the defaults are 320 ms for minimize/restore and 240 ms for opening.

Capture and geometry

WindowSnapshot now uses Windows Graphics Capture (WGC), rather than PrintWindow.
PrintWindow can report successful message handling without a usable GPU client
surface. The previous implementation then forced every pixel's alpha to 255,
making incomplete client frames into opaque white/black rectangles. It also
temporarily changed WS_EX_LAYERED and requested RDW_ERASE during restoration.
Those capture, alpha/style mutation and erase paths have been removed.

The new capture uses an HWND capture item, a free-threaded frame pool, a BGRA D3D11
device and SoftwareBitmap with premultiplied alpha. Pixels retain that alpha in
the WPF Pbgra32 texture. Capture never falls back to a desktop screenshot.

ContentSize must match either the physical DWM extended frame or GetWindowRect.
The latter is cropped to the exact DWM frame. Unknown dimensions, resize races,
oversized buffers and empty/near-uniform frames are rejected. The readiness
filter supplements real compositor capture; it is not a replacement capture
method. A genuinely blank document can consequently receive native behavior.

Capture is limited to one background worker, 12 million pixels per frame, and a
300 ms cancellation budget (140 ms for opening). The dispatcher stops waiting
after 350/160 ms. No source window is modified while waiting for a frame. A
stalled driver can occupy that one worker until it returns; additional work is
not accumulated. Frame, session, pool and device are explicitly disposed on that
worker. No image files are written.

Coordinates remain physical from DWM frame through PointToScreen icon anchor and
mesh camera. Only the WPF host dimensions are converted to its current DPI.
Restore bounds must equal the captured bounds exactly. Display/DPI changes
cancel the surface. Native WINDOWPLACEMENT retains maximized restore behavior.

Handoff and recovery

The animation host renders while clipped by an empty window region. Its pixels
are not displayed over the real window during preparation. Preparation waits for
ContentRendered, two distinct RenderingTime values, the dispatcher render queue
to drain and a bounded DwmFlush in the Dock process. Rendering alone is a
pre-render event, not a presentation acknowledgment. A late/failed flush keeps
the source visible and skips custom motion. One outstanding flush is permitted
so a stalled display driver cannot accumulate workers. A separate process,
running the same WinDock executable in guard mode, then does both handoff steps:
it clips the source to an empty region and reveals the prepared host.

The source's original style, layered alpha and color-key state are never changed.
Windows with an existing explicit region are excluded. Successful SetWindowRgn
calls transfer HRGN ownership to Windows; failed calls dispose the local HRGN.

On completion or cancellation, the guard first removes its source clip, then
clips the host, and only then acknowledges release. The Dock closes the host
after that reply. There is no extra two-frame hold of a duplicate translucent
surface. Both region changes execute consecutively in the guard, without an IPC
round trip between them. Win32 does not provide an atomic cross-process DWM
transaction for these calls; absolute frame-perfect switching is not claimed.

The named pipe is current-user-only and verifies both process IDs. A guard
handshake must finish before clipping. Source identity uses PID, process start
time, a held process handle and per-HWND operation/lease properties. The host
also has a per-HWND lease property and must belong to the parent process.
Recycled HWNDs or PIDs cannot inherit the old lease. Cleanup preserves a newer
nonempty region installed by the application.

Pipe loss, parent exit and a fixed 1400 ms lease initiate recovery. The guard
also clips the overlay if the parent UI has stalled. Recovery does not replay
an old minimize/restore command after a user changes the window's state. The
Dock's release runs in finally; a failed release closes the pipe to request
independent recovery. Capture, IPC and render waiting are cancellable/bounded.

SetWindowRgn itself is synchronous and sends WM_WINDOWPOSCHANGING/CHANGED.
Foreign-window region changes and redraw requests run in the guard process,
not on the Dock UI thread. The guard retains ownership and retries failed
restoration, but a target thread that stops processing Win32 calls can delay
restoration beyond the nominal lease. Killing both Dock and its guard while a
lease is active removes that recovery protection. Normal application exit and
updates must let the guard finish. No process injection or undocumented cloak
interface is used.

Dock minimize/restore

- The active single-window Dock item folds into its actual icon bounds.
- Restore unfolds the recent frame from the preceding Dock minimize. The cache
  is restricted to four windows, 96 MiB and three minutes, with a per-HWND token.
  A minimize performed elsewhere has no such frame and restores natively.
- Repeated Dock clicks retarget the same surface at its current position and
  velocity. Bounds changes, external hide/state changes, changed capture
  protection, focus changes, cancellation or disabled Windows motion end it.
- A 64-row, 4-column WPF3D mesh narrows each row toward the icon before transporting
  it. Filtering uses the full captured pixels. The mesh formula and timeline
  implementation were written independently.

First launch

WindowLaunchObserver registers out-of-context CREATE/SHOW notifications before
the Dock launch. Launcher supplies a receipt from that exact Process.Start call.
A candidate must have the receipt's PID and creation time, the exact requested
EXE path, a held live process handle, CREATE and first SHOW events after the
request, and an HWND absent from the pre-launch window list.

Only a new, foreground, ordinary top-level main window is eligible. Existing
running/background applications, owned dialogs, tool/splash-style windows,
known game classes/paths, URI/AppID launches and unverified launcher-child
processes are not intercepted. No title or install-folder heuristic identifies
a launch. Hooks expire after ten seconds and are removed when no request remains.

The valid frame and prepared surface must be handed off within 180 ms of the
original first SHOW timestamp. The guard checks the same cutoff. A late event,
slow/blank capture, delayed guard, changed geometry or another foreground window
skips animation entirely. No retry later rewinds a fully shown window. The
opening effect expands from 96% at the final location with a small directional
offset; it does not contract a visible window back into the Dock icon. It does
not change the application's activation or placement.

Out-of-context events happen after Windows shows a window. This implementation
cannot promise control of every cold-start application's first visible frame:
one or more native frames may already be visible within the early budget.
Slow first frames and brokered/UWP/single-instance startup paths remain native.

Capture indicator and remaining limits

WGC keeps the normal system capture indicator, which can briefly appear around
the target. WinDock does not suppress it, request borderless access, or bypass
its consent/capability requirements. If capture is denied or unavailable, the
source is left visible and native behavior is used.

Protected, fullscreen, hung, denied/elevated, topmost, custom-region and UWP
frame-host windows are excluded. The implementation does not intercept title-bar
minimize, Win+D, Win+M or Alt+Tab. Ordinary existing layered windows are eligible
only if they satisfy the same capture and region checks; their alpha is not
rewritten. Video and translucent backdrops are frozen during the short motion.
The BGRA8 path does not implement HDR tone mapping; HDR fidelity is unverified.
Native compositor effects are not globally disabled and can still depend on the
application/driver. Large or unstable geometry falls back to native behavior.

The source compiles in Release for net10.0-windows10.0.19041.0. Desktop behavior,
visual quality and compatibility have not been runtime-verified in this change.

Controls and rollback

dock.windowMotion controls Dock minimize/restore; dock.windowMotionDuration sets
its duration. dock.windowOpenAnimation controls opening independently, with
dock.windowOpenDuration for timing. Turning a switch off cancels the active
surface for that Dock; disabling both releases the guard and cached frames.
Set both switches false to retain native window behavior. No source placement,
Windows animation preference or capture permission is persisted by this feature.
