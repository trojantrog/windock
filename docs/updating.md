# 覆盖更新

WinDock 固定安装在 `D:\WinDock`。更新时覆盖这个目录中的程序文件，并重新启动 `D:\WinDock\WinDock.exe`。下载或解压的目录只作为更新来源，日常启动继续使用原安装位置。

关闭正在使用的 WinDock 设置窗口，解压完整的更新包，再从项目目录用 PowerShell 7 执行：

```powershell
pwsh -NoProfile -File scripts/Update-InstalledBuild.ps1 -PackagePath '更新包的完整目录'
```

更新包应包含 `WinDock.exe`、`build-info.json` 和 `SHA256SUMS.txt`，以及校验清单中的全部文件。脚本先核对文件和版本，再请求 WinDock 正常退出。退出失败时停止更新，不强行结束进程。更新完成后自动启动原安装位置的程序，无需打开更新包中的另一个副本。

## 设置和固定应用

设置继续保存在 `%APPDATA%\WinDock`。更新过程不改写这里的文件；显示 Dock、替换 Windows 任务栏、自动隐藏、预留空间、跟随窗口、同步任务栏、更新提醒、动画和外观等选择均沿用原值。始终固定的应用、各环境中的固定应用及其他已有数据一并保留。

WinDock 退出后，脚本备份整个用户目录并校验每个文件的 SHA256。启动新版本前再次核对原文件，启动后比较已有设置和环境文件。新增版本允许补充设置项；已有值、列表内容和未知字段发生变化时，更新会报告错误并保留备份。

原生任务栏的可见性按保存的选择核对。启用 Dock 并勾选“替换 Windows 任务栏”时保留该选择，其他情况下核对原生任务栏可见。

## 登录启动

原有开机启动项缺失时继续保持关闭。已存在的普通启动项若指向旧版 WinDock，脚本将程序路径迁移到 `D:\WinDock\WinDock.exe`；Windows 中的启用、禁用及策略状态保持原样。自定义且无法识别的启动命令保持原样，报告会显示该命令。详情见 [登录启动状态](startup-behavior.md)。

整窗动画登录任务默认只读取和报告状态，已匹配的任务直接复用。更新不会重新启用已关闭的任务，也不会自动弹出管理员确认。只有明确需要登记动画登录任务时才添加 `-EnableAnimationStartup`，该参数仍保留设置页中的动画开关。

## 备份和失败处理

默认备份目录为 `%LOCALAPPDATA%\WinDock\Backups\install-日期时间`，包含原程序、完整用户目录、文件校验清单和安装报告。可通过 `-BackupRoot` 指定另一个独立目录。

程序文件替换失败时，脚本在确认 WinDock 已退出后恢复本次替换的文件和本次迁移的普通启动路径。用户目录不回写旧快照，避免覆盖更新期间保存的新设置。需要恢复某个用户文件时，先核对备份与当前文件，再选择要恢复的版本。

设置页和托盘中的版本下载按钮目前打开发布网页，不会自动下载或安装程序。下载后使用上述覆盖更新命令；直接运行解压目录中的 `WinDock.exe` 会使用那个目录的程序。
