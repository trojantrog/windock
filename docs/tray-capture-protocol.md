# 托盘采集协议

当前本地传输版本为 7。WinDock 在选定的 Explorer 托盘线程安装 `WH_CALLWNDPROC` 和 `WH_CALLWNDPROCRET`，保持原窗口过程和原钩子链。组件与宿主必须使用相同协议版本。v7 使用独立文件 `WinDock.TrayHook.v7.x64.dll`，升级时不覆盖仍可能被 Explorer 持有的旧版 DLL。

## 按处理结果更新

前置钩子复制有效字段和 `HICON`，返回钩子只读取保存的副本及 `CWPRETSTRUCT.lResult`，不再解引用原消息的数据指针。微软规定 [`WM_COPYDATA` 数据只在消息处理期间有效](https://learn.microsoft.com/en-us/windows/win32/dataxchg/wm-copydata)，[`CWPRETSTRUCT.lResult` 是窗口过程的返回值](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-cwpretstruct)。

对本机 `C:\Windows\System32\shell32.dll` 的静态分析确认：`Shell_NotifyIconW` 在调用 `SendMessageTimeoutW` 成功后，将窗口过程结果与整数 1 比较；不相等时返回失败。文件 SHA-256 为 `c55a5f3b6ef059871fe2a0c8d82f086e0998d1154023e3ecf49698b97f9341f6`，函数导出 RVA 为 `0x1b5f0`，结果比较位于 `0x1b9f9`。这只证明该文件上的行为，不构成 Windows 对私有传输协议的稳定承诺。

| 消息类型 | 含义 | 宿主处理 |
| --- | --- | --- |
| 1 | Explorer 返回成功的注册操作 | 按 ADD、MODIFY、DELETE、SETFOCUS、SETVERSION 处理。 |
| 2 | 已核对管道来源的连接建立 | 开始当前连接会话。 |
| 3 | 采集或传输丢失更新 | 显示恢复状态，并限频请求重新注册。 |
| 4 | Explorer 拒绝的 ADD | 仅作为显示补全候选，不改写既知协议。 |
| 5 | 已核实原生对象的当前图像 | 仅更新已有且身份匹配的条目图像，不创建注册或改变回调。 |
| 6 | 当前图像读取状态 | 写入有界诊断，不改变注册与点击协议。 |

被拒绝的 MODIFY、DELETE、SETVERSION 和 SETFOCUS 不更新宿主状态。ADD 成功时才建立默认协议，SETVERSION 成功时才改变协议；ADD 中与超时共用的字段不作为版本。嵌套消息最多保存 32 份副本，按请求进入顺序提交已返回结果，防止内层 SETVERSION 排到外层 ADD 之前。断开连接、发送失败和窗口销毁时释放尚未提交的图标副本。图像转换和管道写入继续在后台线程执行。

## 当前图像与更新顺序

包头继续为 16 字节，小端序：magic、version、kind、length 各 4 字节，length 包含包头。类型 1、4 在原 976 字节固定正文前增加 8 字节序号；类型 3 的正文为 8 字节丢失屏障序号。类型 2 没有正文。序号在该 DLL 存续期间单调增加，不随重连清零。

类型 5 的固定正文为 80 字节，然后是图像字节：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 当前连接 nonce |
| 4 | 4 | 像素格式，1 表示 Pbgra32 |
| 8 | 8 | 图像引用取得时的序号 |
| 16 | 8 | 所属 HWND |
| 24 / 28 / 32 | 各 4 | PID、TID、图标 ID |
| 36 | 4 | 进程实例类型：1 为创建时间，2 为系统进程序号 |
| 40 | 16 | GUID |
| 56 | 8 | 对应类型的实例值，必须非零 |
| 64 / 68 / 72 / 76 | 各 4 | 宽、高、行字节数、像素字节数 |

图像必须为 1–256 像素宽高，行字节数等于宽度乘 4。宿主重新核对进程、窗口、线程、窗口类以及实例类型和值。创建时间路径继续持有进程句柄并确认存活；系统进程序号路径只更新已由当前原生模型确认、实例完全相同的条目，不在界面线程执行系统进程查询。会话不符、所属对象变化、早于丢失屏障或已处理新图像的帧均丢弃。图像不能将未知注册变成可点击项目。宿主先处理注册消息，再处理图像；图像队列独立限制为 16 项、2 MiB，队列满时不会清空注册消息或触发重新注册。

类型 6 的正文为 24 字节：nonce、状态码各 4 字节，序号 8 字节，当前连接累计取得有效图像引用的数量、交给发送队列的数量各 4 字节。发布计数不代表宿主已显示。状态码 0–8 依次为可用、证据不匹配、线程不匹配、注册消息处理中、图像线程忙、对象不可读、像素不可读、取消、队列满。诊断不保存提示文字或像素历史。

宿主通过 `WinDock.TrayHook.Images.v7` 请求图像，参数只有宿主 PID 和 nonce。一次最多取得两个对象；模型恢复后短时每 500 毫秒请求，随后每 2 秒请求。此路径用于补全及刷新当前图像，应用的实时 `NIF_ICON` 更新仍通过类型 1 传输。完整对象与线程证据见 [原生托盘图像](native-tray-images.md)。

## 晚接入与显示补全

[Qt 6.8 的官方实现](https://github.com/qt/qtbase/blob/6.8/src/plugins/platforms/windows/qwindowssystemtrayicon.cpp)在 `TaskbarCreated` 后更新图像并尝试 ADD；仅 ADD 成功后才发送 SETVERSION。这说明向已注册应用请求重新注册，不能保证获取它的版本，也不能把被拒绝的 ADD 当作新注册。

对于失败 ADD，宿主在后台通过 `Shell_NotifyIconGetRect` 确认相同窗口和 ID 的图标仍存在，再补充尚未确认的空显示字段。GUID 查询本身不能证明所属窗口：缺少此前成功操作所建立的 GUID、窗口、进程关联时，不生成候选图标。异步结果会重新核对连接、窗口及进程；已被删除或重新成功注册的候选作废。成功修改过的空图像、空提示或空回调也属于已知值，候选不会覆盖它们。

存在性查询同时最多执行一次，最多保留 32 个候选，每次等待上限 2 秒。若系统的同步查询迟迟不返回，该调用继续占有单个查询位置，新的候选会超时结束，避免累积阻塞线程；不会阻塞 Dock 界面或 Explorer 的窗口线程。

`callbackObserved` 与 `versionObserved` 分别记录回调消息和版本是否来自成功操作。两者都确认、且真实创建时间与严格进程身份校验有效时才允许直接发送点击回调。系统进程序号不能替代该路径的创建时间；这类条目只尝试同一 Explorer 会话中真实可见控件的默认操作，每次提交前重新核验实例。`registrationObserved` 表示是否看到成功 ADD。原生位置查询不会确认版本或回调，不能将版本未知的项目解释为旧版协议。诊断中的 `rejectedRegistrations` 和 `confirmedCandidates` 分别统计被拒绝的 ADD 与通过存在性检查的显示补全。

此实现尚未进行桌面交互验证。晚接入的部分应用仍可能只显示图标，未知 GUID 图标仍可能缺失；Windows 原生任务栏需保留。原生默认操作要求控件真实可见，不包含自动展开已关闭的溢出区、右键菜单、双击第二下或应用自绘悬停内容。

## 运行状态与诊断写入

`tray-status.json` 保存一份当前状态，状态不变时每 30 秒最多补写一次心跳。`observation` 分别记录定时器、图像请求、管道接收阶段、队列清理和模型读取；`writer` 记录上一次写入的排队、开始、完成时间及失败计数。写入始终只保留一个后台任务；忙时合并保留最新一份完整快照，当前写入结束后继续保存它，服务停止后的最终状态也按此处理。写入失败不自行无限重试。不记录提示文字、图像历史或无关进程名称。

文件时间停止变化不能单独证明窗口、图像或管道停滞。若界面不再调用诊断、后台写入本身阻塞，最后一份文件也不会自行更新；必须结合其中不同阶段的时间和其他已有运行证据判断。心跳用于定位停顿，不作为应用菜单或输入法兼容性验收。
